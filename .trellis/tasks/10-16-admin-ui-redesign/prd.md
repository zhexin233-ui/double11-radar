# 管理台视觉重构：编辑式列表 + 分页 + 深色主题（Mantine v9）

## Goal

把管理台从「白卡片里塞表格」改成统一的**编辑式列表**视觉（参考 cssdesignawards.com 的条目分割语言）：
条目之间用发丝分割线与大间距划开，层级靠排版而不是靠面板边框与阴影。

同时交付三件配套能力：

1. **补齐分页**：尚未分页的列表改为服务端分页，所有分页交互统一。
2. **深色主题**：跟随系统 + 手动切换（浅色 / 深色 / 跟随系统），SSR 无闪烁。
3. **引入 Mantine v9**：交互原语（分页、表单控件、开关、对话框、反馈、徽标）改用库组件；
   排版、条目列表、表格外壳仍由 `globals.css` 掌控。

---

## Requirements

### R1 编辑式列表视觉（全部管理页 + 登录页）

- 覆盖：`/status`、`/bulletins`、`/bulletins/[id]`、`/needs`、`/channels`、`/jev`、`/push`、`/login`。
- 去掉重面板堆叠：区块不再是一堆带 20px 圆角 + 阴影的白卡；改用顶部规则线 + 大间距分割。
- 条目区使用统一样式：1px 发丝线分隔、悬停整行反馈、小号字距标签（eyebrow）→ 主标题 → 元信息与操作。
- 窄屏（≤640px）条目竖排，元信息换行，不横向溢出。
- 不引入 Tailwind、CSS-in-JS 自写样式、状态管理库。

### R2 列表分割（核心诉求）

- 条目结构固定：**小标签行**（状态 / 来源 / 时间）→ **主标题**（可点进入详情）→ **元信息与操作**。
- 行内不嵌套可点击元素（标题是唯一链接，操作按钮与其平级）。
- 数据里没有图片字段，条目不放缩略图；视觉锚点由「状态徽标 + 来源 + 时间」小标签行承担，不伪造图片。

### R3 分页（服务端分页 + 统一交互）

- 「需求清单」与「采集频道」改为**服务端分页**（`limit` / `offset` + 总数）。
- 「线报记录」与「Jev 最近调用」已有分页，改用统一分页组件。
- 分页必须显示：总数、当前范围（第 a–b 条）、页码、上一页 / 下一页；禁用态正确。
- 数据缩减导致当前页越界时自动收敛到最后一个有效页，不停在空白页。
- 非法分页参数（非整数、负数）回退默认值，不得 500。

### R4 明确「哪些列表不分页」

- `/status` 的「频道错误」「最近失败任务」：后者服务端硬限最近 10 条；两者是诊断快照。保持不分页，
  并在 UI 上写明条数上限 / 总数，不能看起来像「只有这些」。
- 线报详情的「逐需求判断」「投递状态」：基数由需求数与渠道数决定（十位级 / 2 个）。
- `/jev` 的「按 Key 汇总」与「API 密钥列表」：基数由 Key 池规模决定。
- 以上理由必须写在 `design.md`，不得静默省略。

### R5 深色主题（新增）

- 三种状态：浅色 / 深色 / 跟随系统；首次访问跟随系统，手动选择持久化（localStorage）。
- 切换入口在顶部导航，切换后立即生效，**不得有整页白屏闪烁**（SSR 阶段注入主题属性）。
- 所有自定义 CSS 的颜色必须来自令牌（令牌映射到 Mantine CSS 变量），**禁止硬编码 hex**；
  浅色与深色下都要有可读对比。
- 深浅两套主题下，状态语义色（成功 / 警告 / 失败）必须仍可区分，且与文案标签一致。

### R6 Mantine v9 使用范围（新增）

**用库**（交互原语）：

| 用途 | 组件 |
| --- | --- |
| 分页 | `Pagination` |
| 按钮（含加载态） | `Button`（filled / default / subtle / color=red） |
| 文本 / 密码 / 数字 / 多行输入 | `TextInput` / `PasswordInput` / `NumberInput` / `Textarea` |
| 下拉选择 | `Select` |
| 开关 | `Switch` |
| 勾选 / 单选 | `Checkbox` / `Radio` |
| 凭证分组 | `Fieldset` |
| 删除确认 | `Modal`（替代 `window.confirm`） |
| 反馈 | `Alert` + `Loader`（保留 `Feedback` 的 role / live region 契约） |
| 状态徽标 | `Badge` + 单一状态→颜色映射 |

**不用库**（排版归 CSS）：页面容器、页眉、区块、编辑式条目列表、`table` 元素本身、锚点导航。
理由：这些决定了编辑式观感，交给库会退化成普通后台外观。

### R7 语义与文案契约不变（硬约束）

- 状态一律走 `STATUS_LABELS` / `EVALUATION_LABELS` / `DELIVERY_LABELS` / `EVALUATION_MODE_LABELS` /
  `PROCESSING_SOURCE_LABELS`；徽标颜色可以换库，**文案映射不得另写一套**。
- 「处理失败」不得渲染成「没有匹配」；本地过滤（`stage === "filtered"`）必须显示 `screeningReason`。
- 金额未知一律 `null` 语义：**绝不显示 `$0.00` / `0 元`**；来源未提供价格显示为空。
- 「以下为**程序生成的分类说明**（不是模型生成的理由）」标签保留。
- 凭证编辑必须保留「保留 / 替换 / 清除」三态，空输入永远表示「保留」。
- 所有用户可见文案保持简体中文。

### R8 无障碍与响应式

- 每页恰好一个 `h1`；保留「跳至正文」；焦点可见在各主题下都有足够对比。
- 列表语义正确：条目列表用 `ul`/`li`；表格数据用 `table`。
- 宽表继续走 `TableScroll`（内部横向滚动），不新增移动端专用 DOM，不隐藏列。
- 分页控件键盘可达、有可读标签与禁用态；`aria-current` / `aria-pressed` 用法沿用现有约定。
- 浅色与深色下都不得出现 hydration 警告（尤其主题切换控件）。

### R9 不动的部分（非目标）

- 不改数据库 schema（分页是只读查询，无需迁移）。
- 不改业务逻辑、worker、判定语义、门控 / 正则行为、API 鉴权与同源校验。
- 不引入 Tailwind、shadcn、antd、状态管理库、虚拟滚动。
- 不新增图片资源。

## Acceptance Criteria

- [ ] 8 个页面全部使用同一套令牌与编辑式列表样式；旧 `.card` 面板外观不再出现在任何页面。
- [ ] 线报记录为编辑式条目列表：小标签（状态徽标 + 来源 + 时间）、标题链接进详情、价格、命中需求，条目间发丝线。
- [ ] 需求清单为服务端分页，行内编辑（失焦提交）行为不变；`/api/needs` 返回 `{ items, total }`。
- [ ] 采集频道为服务端分页；跨页选择不丢失，UI 显示「已选 N 个（含其它页）」；`mode=all` 语义不变。
- [ ] 线报记录、需求清单、采集频道、Jev 最近调用四处使用同一分页实现，文案与禁用态一致。
- [ ] `design.md` 记录每处未分页列表的理由；`/status` 两表在 UI 上说明条数上限 / 总数。
- [ ] 分页越界自动收敛，且实现不依赖 `set-state-in-effect`。
- [ ] 深色主题可用：跟随系统为默认，手动可切浅色 / 深色 / 跟随系统并持久化；刷新后不闪白屏。
- [ ] 浅色与深色下逐页走查通过：文字对比可读、状态色可区分、无硬编码残留色（`grep` 校验 `globals.css` 与页面内无裸 hex）。
- [ ] `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 全绿；build 中 `/api/*` 仍为 dynamic（`ƒ`）。
- [ ] 分页纯函数（参数解析、越界收敛、范围计算）与仓库层分页有单测；`tests/service/bulletins.test.ts` 回归通过。
- [ ] 手工冒烟：未登录 `/api/needs` → 401；登录后 6 个管理页 + 详情页在浅色 / 深色下均正常；375px 无整页横向溢出。
- [ ] dev console 无 hydration 警告（含主题切换控件在首屏的表现）。
- [ ] 文案契约抽查通过：状态标签、未知金额、程序生成说明、处理失败 ≠ 没有匹配、凭证三态。
