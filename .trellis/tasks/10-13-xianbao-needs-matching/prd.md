# 线报需求匹配与推送

## 目标与用户价值

在本地NAS持续监控线报酷，以TypeSafe Jev将线报商品与用户的购买需求清单进行语义匹配，把明确相关的新线报推送到Bark和飞书，减少用户手动筛选线报的时间。

状态：用户已批准最终方案，但明确要求当前暂不进入实施。任务保持planning；收到后续开始执行指令后可实施，无需重新创建任务或再次确认相同方案。

## 背景与证据

当前仓库没有业务代码或现成模型、采集、通知模块。外部协议通过smart-search CLI核验，已保存：

- `research/repo-inventory.md`：空业务仓库与框架模板现状。
- `research/xianbao-source.md`：官方公开API、字段结构、能力清单、缓存、限流和最新快照限制。
- `research/jev-api-compatibility.md`：用户确认采用TypeSafe Jev，原生System One API只返回结构化决策，不生成文字。
- `research/notification-channels.md`与`research/feishu-notifications.md`：Bark参数、飞书群Webhook、签名和业务成功判定。

## 需求

### R1 网页与访问

- 提供单管理员密码登录，不做注册和多账号管理。
- 网页管理需求清单、采集频道、Jev配置、Bark和飞书配置，查看线报、判断及投递状态。
- 需求清单最小字段为名称和可选自然语言备注，支持新增、编辑、启停和删除；例如“抽纸，不要湿巾”。无需用户穷举品牌关键词。
- 支持测试模型连接和分别测试两个推送渠道；未登录不能访问配置、记录或执行这些操作。
- 配置读取不回显模型密钥、设备Key、Webhook和签名密钥原文；编辑支持保留、替换及显式清除已保存凭据。

### R2 来源与新线报

- 采用线报酷官方公开API拉取，网页可选频道，默认全部开放频道。
- 首次成功获取每个频道快照时建立基线，已有条目不调用Jev、不通知；之后新出现的条目才进入处理。
- 初始化失败可恢复，重启沿用持久化采集状态，不重新回推已有条目。
- 全部频道与自定义选择保存后生效；个别频道暂时失败不清空选择，也不阻塞其余频道。
- 分类流与值得买独立流字段不同，分别适配；保留原始标题、链接、来源类别、时间及可选价格/商品字段。

### R3 TypeSafe Jev匹配

- 使用原生System One接口，网页可配置服务地址、模型标识、API密钥和超时，并执行连接测试。
- 结合线报标题、正文及可用商品字段，对每项启用需求返回匹配、不匹配或信息不足。
- 仅品牌相关不能等同品类匹配；同品牌抽纸、湿巾、卷纸必须区分。软抽等语义描述应能匹配抽纸。
- 仅明确匹配进入通知；信息不足留在网页待确认。不合法结果或模型调用失败标记处理失败，不伪造命中。
- 保存需求关联、分类、概率/置信度及所用配置版本。展示原始标题和程序生成的分类说明，不把模板说成模型生成理由。
- 一条线报命中多个需求时在同一条通知中列出命中项。

### R4 推送与恢复

- 首版Bark配置一个设备，飞书配置一个群自定义机器人Webhook；两者独立启停。
- 明确匹配发送到所有已启用渠道。全部关闭时仍保留网页判断记录。
- 通知包含命中需求、原始标题、分类说明和原始线报链接；来源明确提供的价格/条件可展示，不宣称低价。
- 飞书支持可选签名密钥，使用富文本链接；必须检查业务返回码，不能仅凭HTTP200判定成功。
- 各渠道分别保存投递状态；一个成功、另一个失败时只重试失败渠道。避免本地重复处理重新发送已成功任务。
- 可以查看失败原因并重试；网络超时的未知结果不能承诺绝对零重复或用户已读。

### R5 NAS运行

- Docker部署在本地NAS，局域网网页负责配置，后台独立持续运行，关闭网页不停止采集或判断。
- 配置、清单、已见线报、未完成任务、判断与投递记录持久化，重启或重建容器后保留。
- 网页提供后台状态和最后处理时间，区分没有匹配与处理故障。

## 验收标准

| 编号 | 对应需求 | 可观测结果 |
| --- | --- | --- |
| AC1 | R1 | 管理员能登录/退出；未登录直接调用配置、记录、测试或重试API被拒绝；配置读取无原文凭据 |
| AC2 | R1/R3 | 网页添加/编辑/停用需求后影响后续任务，重启保留；设置Jev后能完成原生接口连接测试 |
| AC3 | R2 | 默认全部开放频道，自定义选择保存有效；频道失败可见且不清空配置或停止其余频道 |
| AC4 | R2 | 首次快照不产生模型调用或通知，新条目进入判断；初始化失败后可恢复，重启不回推基线条目 |
| AC5 | R3 | “心相印超韧抽纸”“维达软抽”匹配抽纸；“心相印湿巾”“心相印卷纸”不匹配 |
| AC6 | R3 | 只有“心相印9.9元”且没有更多商品信息时标记待确认，两个渠道均不发送 |
| AC7 | R3 | 多需求结果正确关联；未知Choice、缺失答案、类型不符或调用超时不会被当作命中；说明不冒充模型生成理由 |
| AC8 | R4 | Bark与飞书能分别保存/测试/启停；同时启用时收到明确匹配通知及可打开的原文链接，多个命中项合并显示 |
| AC9 | R4 | Bark成功且飞书失败，只重试飞书；飞书业务非零码不被记为成功；已有成功任务本地重放不重复发送 |
| AC10 | R4 | 两渠道关闭时不通知且保留判断记录；没有历史低价标签；价格缺失保留为空而非0元 |
| AC11 | R5 | Docker部署后关闭网页后台仍处理；重建容器能恢复配置、解密凭据并继续未完成任务 |
| AC12 | R2/R5 | 能力清单、采集或模型服务失败显示明确状态，不显示成“没有匹配”；按限流退避并可恢复 |

## 本期不包含

- 用户历史低价导入、单价归一化、低价判断和自动下单。
- 其他模型提供方、OpenAI聊天适配、额外生成模型、模型生成匹配理由。
- 历史线报批量回放、飞书应用/个人消息、多设备、多群、多账号或按需求指定通知渠道。
- 不同文章的跨文章活动合并；以原始来源身份去重。

## 技术约束与延后验证

- 官方普通分类流仅保留最新20条、值得买30条，无完整历史分页。全频道高峰或长时间停机可能遗漏，榜单不构成完整补齐。
- 原始meta JSON未被网页抓取工具成功提取；文档协议已核验，实际响应字段与目标NAS架构在实现接入时核对。
- 未使用真实模型或推送凭据验证端到端。实现阶段用固定样例验证流程；用户在网页配置自己的凭据后验收真实连接，不要求在聊天提供密钥。
- Jev的概率/置信度不直接等同本场景准确率；语义正反例与保守Choice规则需要样例验证。

产品决策已收敛，无阻塞需求问题。完整方案的批准已取得，执行时间按上方状态约束。
