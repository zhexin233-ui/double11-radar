# 全站布局与技术设计

## 设计目标与依据

用户确定采用 Apple 官网式展示方向并覆盖全站。设计以大标题、宽留白、连续区块和克制配色建立阅读节奏，重点展示真实运行信息与操作内容。官方依据及代码证据分别见 `research/apple-reference.md`、`research/current-ui.md`。

以下尺寸是本项目的实施起点，并非 Apple 官方参数。完成首轮桌面/窄屏截图后允许在同一方向内微调，不改变范围或业务语义。

## 页面结构

```text
顶部：品牌 | 六个管理入口 | 退出
标题：页面定位 / 大标题 / 一句说明 / 主要操作
正文：白色与浅灰区块，保持共同内容边界
      区块标题 → 关键信息或工具栏 → 表格/表单/正文 → 相关反馈
```

- 保留顶部导航，桌面单行；窄屏品牌/退出一行、入口一行横向滚动，活动入口可见。导航是普通链接，不添加复杂菜单状态。
- 管理壳层与登录采用显式容器类，逐步去除裸 `main` 对宽度的全局控制；导航、标题和正文共用容器变量。
- 内容上限 1200px，桌面内边距 32px、窄屏 20px；主要阅读正文上限约 760px，表格与多列区块可占内容全宽。
- 标题区桌面上下留白约 56–72px，窄屏约 32–40px；不设固定视口高度。第一块有效内容在常见桌面视口中可见，不增加介绍口号或重复数据。
- 区块内桌面 32px / 窄屏 20px；区块间 32–48px。说明紧邻相关字段，错误紧邻动作所属区块。

## 视觉规则

| 项目 | 方案 |
| --- | --- |
| 颜色 | 白色 `#fff`、浅灰 `#f5f5f7`、正文 `#1d1d1f`、辅助正文 `#626267`、蓝色主操作 `#0066cc`；成功/警告/失败保留独立语义色，最终实测对比度 |
| 字体 | 保留系统字体栈；页面标题用响应式字号约 36–64px，区块标题 24–32px，正文/表单 16px，表格与元数据 14–15px；长标题自然换行 |
| 间距 | 以 4/8/12/16/20/24/32/48/64px 建立令牌，避免每页单独定义 margin |
| 表面 | 主区块圆角约 20–24px，表单控件约 10–12px；细分隔线，阴影只用于确有层级的浮层；避免每个数据项套多层卡片 |
| 操作 | 蓝色主操作、弱化次操作、文字明确的危险操作；不靠颜色或图标单独表达功能；点击区域至少约 44px |
| 状态 | 状态徽标保留中文文本，正文不使用过浅灰；关键异常和未知计费文字不折叠、不淡化 |
| 动效 | 仅短暂的颜色/透明度反馈；尊重 `prefers-reduced-motion`；不添加滚动触发入场、视差或大范围模糊 |
| 主题 | 浅色；不增加主题设置和新依赖 |

颜色验收以普通文字至少 4.5:1、大文字及必要图形/控件至少 3:1 为基准；选色需结合实际背景检查。

## 各页布局

| 页面 | 标题与首要内容 | 后续区块与操作 |
| --- | --- | --- |
| 登录 | 简洁品牌、明确登录标题与短说明 | 单个限宽约 440px 表单，密码标签/错误/登录动作；窄屏保持舒适边距 |
| 运行状态 | “运行状态”大标题＋真实健康摘要＋刷新 | 关键统计采用大数字与短标签；进程、采集/任务、处理、投递按组展示；异常紧随摘要，不沉到底部 |
| 线报记录 | 大标题与说明 | 筛选/刷新/自动刷新在数据区工具栏；五列表格与结果数/分页明确分区，单条标题仍是详情入口 |
| 记录详情 | 返回记录、可换行标题、状态与来源元数据 | 原文阅读区 → 程序分类说明与逐需求判断 → 各渠道投递/重试；原始链接可访问，长 URL 可断行 |
| 需求清单 | 标题、作用范围简述 | 新增需求区 → 现有需求编辑列表；保留失焦保存，启停和删除靠近所属需求；不悄悄改为统一保存 |
| 采集频道 | 标题＋选择/基线/错误摘要 | 模式选择、清单刷新 → 频道表与错误信息 → 明确保存动作；现有轮询和 keyed 表单边界保留 |
| Jev | 标题与已知 Key/连接状态，不新增探测请求 | 页内锚点导航：连接与调度 / API 密钥 / 费用与用量 / 需求试判；每区有标题和相关操作，费用警示与测试计费提示直接可见 |
| 推送渠道 | 标题、两渠道独立工作的说明 | Bark 与飞书各自区块，宽屏可双列、窄屏单列；保留一个配置表单和统一保存，渠道测试仍独立 |

Jev 使用页内锚点而非卸载式标签页：四区保留挂载，避免切换时丢失输入或重启请求。锚点设置滚动偏移。逐个保留既有 key 表达式及触发条件；样式、锚点与组件抽取不能改变重挂载边界。Jev/推送配置使用 `data.version`；频道选择使用 `selection.mode` 与 `customIds` 组合（`src/app/(admin)/channels/page.tsx:192`）；Jev 密钥行使用 `item.id` 与 `item.updatedAt`（`src/app/(admin)/jev/page.tsx:655`），不得统一替换为版本字段。

## 响应式与访问能力

- 按可用空间适配：约 768px 以下单列，较宽时分组双列；1024px 左右检查导航与工具栏是否需要换行，必要时继续使用入口滚动。
- 表格放入 `TableScroll` 区域，只对该区提供横向滚动，配置可访问名称与键盘滚动入口；不隐藏业务列、不复制另一套移动端数据 DOM。
- 表格/网格子项 `min-width: 0`；URL、错误和长中文内容可换行；金额/状态等短字段按需保持不换行。
- `:focus-visible` 清晰；语义 `header/nav/main/section`、单页一个 `h1`、层次化 `h2`；提供跳至正文入口。
- 活动导航按精确路径或路径段前缀匹配，不用简单字符串前缀误匹配；记录详情属于记录入口，链接使用 `aria-current="page"`。
- 表单保留原生 label、fieldset/legend、required、disabled、提交行为和确认；成功反馈用礼貌 live region，操作错误采用可感知提醒；不让轮询反复朗读全部内容。
- 刷新保留已加载内容，加载提示不触发表格整体重挂载；不通过排序/DOM 替换打断正在编辑的输入或焦点。

## 代码组织与边界

- `src/app/globals.css`：集中令牌、页面容器、标题、区块、控件、表格、状态及媒体规则；限定新增布局类，迁移时检查全局元素选择器影响。
- `src/components/AdminNav.tsx`：保留路由/退出逻辑，调整导航结构、激活和访问属性。
- `src/app/(admin)/layout.tsx`：保留服务端会话检查，仅调整展示壳层、跳转目标与正文容器。
- `src/components/ui/`：按实际复用提取 `PageHeader`（标题/说明/操作）、`Section`（标题/说明/内容）、`TableScroll`（可访问滚动容器）、`Feedback`（成功/错误/加载文本）。只承载展示，无 fetch、领域状态和通用表单引擎。
- 页面继续拥有数据 hook、mutation 和业务状态；`api-types.ts` 标签/常量继续是唯一来源。
- Jev 页可将既有展示子组件整理到 `src/components/jev/`，仅在主体迁移稳定后按实际收益决定是否移动；不为了缩短文件拆散 keyed 表单，不创建抽象调度或第二套刷新 hook。
- `DryRunPanel` 采用同一视觉规则，保留输入、样例、真实调用提示和结果语义。

## 兼容性与数据流

既有 `useApiResource → api-client → /api/*`、事件 mutation → reload、既有 key 条件变化 → 对应表单重建的链路保持不变。客户端不得导入 `@/lib/**`，通用 UI 组件只接收有类型的 props。

不增加 API、数据库迁移、Cookie 或运行时配置。列表筛选、分页大小、轮询周期、未知费用、Key 禁用恢复及凭据三态沿用现有契约。样式重构不能重新标注程序说明为模型理由。

## 风险与回退

- 视觉调整由全局 CSS 扩散：先建立基线，分块迁移；共享层每次修改均检查登录、数据表和长表单。
- 大字号/留白挤压内容：限定标题区留白与阅读宽度，窄屏缩小间距，不裁切实际数据。
- 组件抽取导致 key/focus/轮询变化：先视觉后可选文件拆分，按现有控制器测试和交互矩阵回归。
- 没有现成视觉测试框架：使用浏览器采集前后截图和操作记录，不能以 node 单测通过替代视觉验收。
- 无数据库迁移；可回退本任务对应的前端提交恢复原界面。不得回退用户或其他任务的无关改动。

## 任务组织

保持单任务、分阶段执行：共享样式、导航及各页面组成同一项全站一致性验收，当前不拆独立子任务。每阶段都可审查与回退，最终按全部页面统一验收。
