# Jev 多密钥并发、费用统计与线报记录筛选刷新

## 目标

提高新线报判断吞吐量，减少重复输入与不必要调用，让管理员看见 Jev 美元费用并便捷查看持续更新的处理记录。

## 当前事实与证据

- 当前每条线报已将全部启用需求合并成一次请求，需求通过稳定 question ID 独立关联：`src/lib/worker/evaluator.ts:76`、`src/lib/jev/prompt.ts:56`。本期保持这种语义，不能把多需求变成互斥选项或用关键词预筛去掉需求。
- 当前只有单 Key，已有全局并发设置（1—8，默认 1）和每轮任务数（1—50，默认 3）：`src/lib/service/config.ts:118`。没有 Key 池或 Key 失败计数。
- 目前响应允许原样 usage，但所有调用入口均未持久化用量：`src/lib/jev/types.ts:25`、`src/lib/worker/evaluator.ts:91`。
- 线报列表目前排除基线记录、每次显示最近 50 条并无条件 30 秒刷新：`src/app/(admin)/bulletins/page.tsx:23`；API 不支持状态筛选：`src/app/api/bulletins/route.ts:9`。
- 2026-10-14 核实官方 Jev 1.13 / `jev-1.13.0` 输入价格为 $0.042/百万 Token、输出免费，`jev-latest` 当前指向它。一次请求共享 state，多 questions 仅增加问题自身的 Token，合并可减少重复输入费用。来源：[官方模型](https://docs.typesafe.ai/models.md)、[多问题说明](https://docs.typesafe.ai/primitives.md)，本地 `research/pricing-models.md`、`research/pricing-primitives.md`。
- 官方 usage 为 `input_tokens`/`output_tokens`；Python 文档明确未报告项可以为空。美元费用需按用量和费率计算并标为估算。来源：[响应契约](https://docs.typesafe.ai/sdk/python/api/types/responses.md)，本地 `research/pricing-responses-python.md:44`。

## 需求

### R1 多 Key 并发与禁用

- 支持安全保存多个 Jev Key，记录独立启用/禁用状态和失败计数；只在服务端解密使用，网页读取保持掩码。
- 多条线报能通过不同可用 Key 并发处理，继续遵守全局并发设置；不将 Key 数量乘以全局并发上限。
- 用户于 2026-10-14 选择方案 1：同一 Key 连续三次实际请求失败自动禁用，成功一次清零；包含认证错误、超时、429、5xx 和非法响应。没有发出上游请求的本地错误、调度等待不计入。
- 禁用 Key 停止新请求分配，其他可用 Key 继续处理；失败计数与禁用状态重启后保留。禁用后由管理员手动恢复或替换密钥，计数重置，不因迟到的成功响应自动重新启用。
- 保留既有单 Key 配置，提供可验证的存量兼容；全池不可用时展示可恢复的配置问题，不错误标成没有匹配。
- 多个并发结果按完成顺序统计连续失败；达到阈值时已发出的请求允许完成并记录用量。替换前请求不改变替换后新密钥的失败计数。

### R2 同线报需求合并

- 一条线报的启用需求共享 state，默认一个请求携带全部 questions，例如抽纸、卸妆膏各为独立问题。
- 结果按 question ID 关联需求快照，保持三态判断、非法答案不伪造命中和多个命中合并通知。
- 尊重官方 64k 总上下文、state 加最长问题 32k 的限制；极长内容/大量需求的越界处理在技术设计中明确，不以字符数冒充精确 Token 数，不静默遗漏需求。

### R3 美元费用统计

- Jev 配置页展示应用新增统计之后的美元估算费用及用量，不能由历史 evaluations 倒推既往账单。
- 每次实际请求记录用量、所用 Key 的非敏感身份、模型、请求来源（后台/连接测试/需求试判）、状态和价格依据；重试是新的实际调用，分别记账。
- 所有 Jev 调用入口一致记录费用；试判继续不写判断/通知/队列记录，用量账本是本期明确增加的副作用。
- 有 input_tokens 且有对应价格时按公布费率计算，缺失输入用量或未知模型价格标为未知，展示未能计价的调用数，不能显示为 $0；仅缺失 output_tokens 不影响当前仅输入计费的估算。
- 保存请求发生时的模型与费率快照，价格更新不得改变历史估算；不得把估算表述为服务商实付账单。

### R4 状态筛选与五秒刷新

- 记录列表增加「全部、等待判断、明确匹配、待确认、处理失败、没有匹配」筛选，保持现有基线排除行为。
- 筛选在服务端分页之前执行，items 与 total 使用一致的状态判定；不能仅过滤当前 50 条。
- 增加可启停的五秒自动刷新控制，默认关闭，保留手动刷新；刷新保留当前筛选与页码，关闭后停止定时请求。
- 慢请求不叠加；切换筛选后旧响应不能覆盖新筛选结果，离开页面清理定时器和在途处理。

## 本期边界与证据限制

- 不修改需求语义、通知渠道、历史线报基线策略；不引入额外模型或依赖服务。
- 本地费用是公布价格下的估算，不提供账户余额、官方账单同步、未知缓存折扣或定制合同价格保证。
- 官方暂未核实多 Key 是否共享组织/账号限额；不承诺增加 Key 就按数量增加额度。429/529 尊重 Retry-After 和退避，同时按用户选择计入失败；临时平台故障可能导致全池禁用，需要手动恢复。
- 官方价格随 `jev-latest` 变化有风险；未知响应模型必须显示无法计价，不能套用无证据价格。
- 当前租约只有 60 秒且会提前领取排队任务，允许的请求超时为 120 秒，存在被过早回收风险。并发设计必须核实并处理这一边界，见 `research/current-behavior.md`。
