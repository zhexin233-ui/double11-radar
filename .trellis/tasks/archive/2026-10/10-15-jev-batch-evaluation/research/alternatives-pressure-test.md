# 替代路线复核：区分减少 HTTP 与减少模型判断

日期：2026-10-15。用户追问“没有更好的方法吗？”。两名只读子代理分别做独立策略核验和严格结果复用的代码探索；没有运行产品测试、读取真实线报库、部署模型或调用 JEV。

## 当前用户约束的正确理解

- 主目标是减少实际 JEV HTTP 请求，价格判断仍有未决口径。
- 用户否定正则规则覆盖不全就跳过；这不等于每条必须直接请求 JEV，也不等于已接受统计模型的漏报率。
- 应比较各路线带来的具体减少对象、部署成本及漏报，不能只换成 embedding 或语义缓存的名词后宣称不再遗漏。

## 方法排序与边界

| 方法 | 减少什么 | 关键限制 |
| --- | --- | --- |
| 独立问题打包 | HTTP 次数、连接及调度开销 | 判断数量不变，Token/费用不必减少；需要满足每题及整包预算 |
| 完全相同有效输入复用 | 重复的 JEV 请求与判断 | 只适用于有效输入严格相同且结果仍有效；真实重复率尚未知 |
| 本地 embedding 候选检索 | 仅在排除未召回项时减少 JEV 判断 | 低分不等于不相关；只排序后仍全量送 JEV 不省判断；引入本地模型与索引 |
| 本地分类器或 cross-encoder 级联 | 本地处理明确结果，将候选/不确定交 JEV | 需要模型、真实标注/阈值校准、硬件验证和漂移维护；置信分数不保证正确 |
| 整批或二分 OR 门控 | 大量阴性分组中的后续判断 | 祖先假阴性会剪掉整组；阳性多时增加请求与延迟 |
| 近似语义结果缓存 | 相似输入的后续判断 | 相似度不能证明结论相同；价格、型号、条件、否定等微小差异可翻转结果，不推荐直接复用 |

不新增模型的优先基线是打包＋严格复用；若希望进一步减少 JEV 需要处理的线报数，本地语义级联值得评估，但尚无本项目收益或准确率证据，不能承诺优于 JEV 或正则。额外模型也不是免费资源，需要 NAS 运行能力与维护成本。

## 严格缓存的代码依据

- `src/lib/worker/evaluator.ts:90`—`:109`：每个 job 均构造输入并调用统一服务，没有跨来源输入查缓存。
- `src/lib/domain/constants.ts:24`—`:41`：contentVersion 基于 `title|content|category|price|brand|mall` 的字段拼接哈希并截为 16 字符，字段分隔未转义；不能以此证明完整模型输入严格相等。
- `src/lib/jev/prompt.ts:82`—`:103`：state 包括标题、正文、品类、品牌、商城、价格；需求文字在 `:40`—`:65` 的 questions 中，question ID 在 `:27`。请求身份必须包括实际 questions，不只是正文。
- `src/lib/db/migrations.ts:117`：来源身份按 `(source, source_ns, source_id)` 唯一；`src/lib/db/repos/bulletins.ts:59`：已有身份不更新。严格复用不得改变来源文章的身份保留行为。
- evaluation 唯一键为 `(bulletin_id, need_id, rule_version)`：`src/lib/db/migrations.ts:161`；版本快照冲突时覆盖：`src/lib/db/repos/evaluations.ts:82`—`:93`。这些键不能直接充当新的跨来源缓存键。
- 通知按 bulletin 独立，deliveries 按 notification/channel 独立：`src/lib/db/migrations.ts:139`、`:179`，`src/lib/notify/dispatch.ts:85`—`:103`。判断复用不是跨文章通知合并。

候选缓存须以无歧义序列化的完整有效输入、需求/规则快照、模型与 provider 身份、相关状态为依据，保存并核验严格相等。仅复用有效答案，失败/缺题不作为可复用判断。并发同时 miss 需合并真实调用，结果仍在每个 job 的租约和事务约束下写各自记录。

价格/规格/数量/优惠/有效期等若参与判断，必须进入输入与身份；依赖“现在”或历史参考价时还须有有效期或状态版本。当前 `publishedAt/url/payload` 不进入 state（`src/lib/jev/prompt.ts:82`），不能简单认为当前相同 state 就在未来价格功能下永远等价。模型别名变化、真实上游非确定性和版本更新也需要保守失效规则。

## 如何用证据收敛方案

1. 准备真实需求与线报的人工核验集，覆盖同义词、品牌关联、否定、罕见需求、多需求、长文本和价格/规格/优惠边界。不能把现有 JEV 输出单独当真值。
2. 按时间/来源切分训练或调参数据与最终测试集；隔离近重复，防止缓存与模型评估虚高。
3. 同时报告 HTTP 调用数、JEV 判断题数、Token/费用、未知用量和延迟。严格复用先统计重复率，不预报节省比例。
4. 对任何本地级联报告整体及逐需求召回率、误报、各阶段引入的漏报、样本数与不确定性；展示收益—漏报取舍，不编造统一阈值。
5. 离线零漏报不等于未来零漏报；额外模型是否纳入范围需用户选择，质量门槛和运行资源再据实收敛。

## 当前最高价值的范围问题

是否接受在 NAS 新增本地语义模型及维护成本？推荐将其作为离线评估候选，用数据决定是否上线；若不接受，就聚焦不新增模型的严格复用与请求打包。此前 5 秒凑批、批量结果使用方式和价格口径均未批准，不在本轮默认为已解决。
