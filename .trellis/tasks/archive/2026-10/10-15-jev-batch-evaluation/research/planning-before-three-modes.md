# 线报过滤与 JEV 调用优化规划

## 目标与用户价值

优化新线报的 JEV 判断方式，以减少实际请求次数为首要目标，并分别核实输入用量、估算费用、处理等待与漏判影响。用户提出：每批新增线报先整体判断一次；整批没有命中则全部记为未命中，存在命中再逐条判断。用户于 2026-10-15 同意创建任务并规划，并明确“看重减少请求次数”；这不等于已接受具体准确率损失或已选择最终策略。本轮不进入实现。

最新约束：用户否定正则前置方案：“这个方案也不好，没覆盖的就被漏掉了。”因此不允许以关键词/正则覆盖范围决定哪些新线报进入语义判断；减少请求仍是主目标，但不能通过规则未覆盖就跳过来达成。用户随后追问是否有更好的方法，不能把“拒绝正则覆盖遗漏”过度推导成“每条必须发起 JEV 请求”。本地模型方向现已明确放弃，不再继续硬件选型、部署或将其作为当前候选。

历史研究：曾核实 NeoHorse-Jev-4B、AutoTrust JEV-9B/27B、NLI 和通用 Qwen 小模型，见 `research/local-decision-models.md`。用户现明确“放弃这个方向，还有别的方向吗”，按上下文指放弃本地模型路线，主任务继续规划。资料仅留作历史，不再索取 NAS 硬件信息。

## 已核实背景

- 目前每条线报只请求一次 JEV，全部启用需求在同一请求中分别回答，并非每项需求一次请求：`src/lib/worker/evaluator.ts:85`、`src/lib/jev/prompt.ts:56`。
- 输入包含标题、接口返回的正文及可用商品字段；不能假定标题足以替代现有输入：`src/lib/jev/prompt.ts:82`。
- 当前采集仅为去重后新条目创建逐条任务，没有持久化的批次成员关系；采集快照、采集轮次和判断轮次不是同一批次：`src/lib/worker/collector.ts:195`、`src/lib/worker/evaluator.ts:265`。
- 判断保留明确匹配、明确未命中、待确认和处理失败；只推送明确匹配。未知或缺失答案不会自动重试：`src/lib/jev/prompt.ts:135`、`src/lib/worker/evaluator.ts:119`、`src/lib/worker/evaluator.ts:228`。
- 所有实际请求必须经过统一服务与调用账本，继承现有 Key 池、容量和退避约束：`src/lib/service/jev-requests.ts:327`。
- 仓库已有按输入 Token 计费的本地费率快照，不能根据请求次数直接推导费用下降：`src/lib/jev/pricing.ts:33`。该证据并非本次重新核验的实时价格。
- 用户提出 32k 上下文约束后，2026-10-15 经 smart-search 抓取官方 Models 核实：`state + 最长问题 ≤ 32k`，`state + 全部问题 ≤ 64k`。每题共享完整 state，定位单条字段不缩短该题看到的 state。官方另提示无关 state 增大会降低准确率，见 `research/context-budget.md`，不能将“装得下”当作“准确率不变”。
- 当前需求仅有名称、备注、启停和版本，没有正则、关键词或结构化目标价格字段：`src/lib/domain/types.ts:41`。来源价格只是 `item.price` 的有限数字，没有标准化实付价、计价单位或历史价；通知明确其不代表券后实付：`src/lib/sources/xianbao/normalize.ts:34`、`:64`、`:99`，`src/lib/notify/types.ts:57`。JEV 当前仅返回三态分类，不能视为已有可靠金额提取能力。
- 官方设计文档支持在每个问题的 instructions 中携带该题专有的数据、示例或记录，问题独立评估。可研究将每条线报放在其独立问题、公共规则放 state 的请求打包方式，降低共享 state 的无关内容；这是新候选，尚未实测，见 `research/independent-question-packing.md`。
- 目前没有跨来源完全相同输入的判断缓存，`contentVersion` 也未用于复用。它不能直接充当严格缓存键（字段拼接与截短哈希不构成输入相等证明）：`src/lib/domain/constants.ts:24`、`src/lib/worker/evaluator.ts:90`。来源身份和通知仍各自独立，新增缓存不能擅自合并文章或通知。
- 2026-10-15 核实中文 BGE-small/base 分别约 0.024B/0.102B，BGE-M3 约 0.569B，官方运行时支持 CPU。前两款 512 Token 上限，长正文需另定分段方案；它们是向量编码器，不能直接视为业务分类器。运行内存和新增功耗尚无 NAS 实测，详见 `research/local-model-hardware.md`。
- 本地专用决策候选 NeoHorse-Jev-4B 提供 Choice/Noul/Score 与 `/v1/systemone` 风格接口，但官方测试部署路径需要 CUDA BF16 GPU，骨干约 9.08GB，默认输入限额与 TypeSafe 不同。AutoTrust JEV-9B/27B 是独立开源学生模型，非 TypeSafe 官方权重。通用 Qwen 2B/4B 与 NLI 可评估 CPU 路线，但不能假定其概率校准或业务质量等同 Jev。

详细定位与方案比较见 `research/strategy-evaluation.md`、`research/independent-question-packing.md`、`research/alternatives-pressure-test.md`。已被用户否定的正则方案及其价格事实保留于 `research/regex-price-evaluation.md`，不得继续作为当前路线。

## 需求草案

### R1 新线报范围与优化效果

- 首要优化指标为实际 JEV 请求次数，包含批量请求、拆分、回退和重试，不以名义批次数代替；费用与延迟为观察指标，不以 Token 最少作为首要目标。具体准确率取舍仍待确认。
- 保留首次快照基线、来源身份去重和历史记录行为；不因本次策略调整自动回放历史线报。
- 每条去重后的新线报都须有语义处理路径；不能因词表未覆盖、正则未命中或未经批准的候选缩减而省略判断。目前以全部需求参与现有 JEV 判断作为基线；严格相同有效输入复用可作为候选，不要求每条重复发 HTTP。模型错误、输入超限或调用故障须可见、可恢复，不能宣称模型绝对零漏判。
- 对同一组输入分别报告实际请求数、已知输入 Token、估算费用及未知用量数量、处理延迟和命中差异，不把模型置信度当作业务准确率。

### R2 判断完整性与异常语义

- 基线方案下每条线报仍能查看全部启用需求的独立语义判断及版本，多个需求命中仍合并为一条通知。若最终另行选择云端模型初筛，必须明确其结果与 JEV 结果的展示、追溯和质量验收，不能冒充全部由 JEV 判断；该云端路线目前仅提出供比较。
- 请求失败、限流、缺答案或非法结果不能转成整批明确未命中；信息不足必须保留待确认语义。
- 正则前置硬过滤已被用户否定，不纳入当前候选；纯本地规则结果不得冒充模型结果。
- 最初整批门控方案保留为比较资料，当前不推荐：一次门控假阴性可跳过所有成员，不能以合并请求为名引入整批语义剪枝。
- 若选择小批量逐项判断，必须校验每个预期线报与需求的对应关系，异常项可恢复且不覆盖合法项；具体回退方式待方案确认。

### R3 持久化、追溯与兼容

- 处理过程中修改需求不能将旧需求下的否定结果应用于新需求；同一批判断须有一致、可追溯的需求快照。
- 重启、租约回收和重试不能漏掉成员或重复创建通知；失去租约的结果不能覆盖新处理结果。
- 每次真实请求独立记账，能追溯涉及的线报；批次推导结果不能冒充逐条模型答案或复制整批概率为逐条置信度。
- 保留现有逐条处理的可回退路径，不引入本地模型部署依赖。额外云端模型或服务尚未批准，不以提出替代思路直接扩大实现范围。
- 打包方式变化不能改变原线报内容与需求含义；保存每个 question 对应的线报及需求快照，规则版本可追溯。

### R4 上下文预算与请求打包

- 任一候选策略均须满足每题 32k 与整请求 64k 两道输入限制；整批预筛同样受限，不能假定全部新条目一定能放进一次请求。
- 批次按实际输入规模动态缩小，不能固定承诺 10 条一批，也不能依靠静默截断正文来满足限制。较长线报独立处理；单条仍超限时保留明确失败或另行批准的处理方式，不伪造未命中。
- 稳定的 Token 计数方式和安全余量仍待技术核验；不能以通用 tokenizer 或中文字符数冒充 JEV 的精确计数。
- 优先研究公共规则为 state、线报内容及目标需求为题目专有上下文的打包方式；每个预期线报×需求组合仍有独立结果。多需求可能重复携带正文并增加 Token，须按总问题量拆请求，不能宣称免费增加容量或默认准确率相同。
- 为提高合并机会可考虑有上限的凑批等待，但等待时限是用户尚未决定的延迟取舍；不能无限积压等满批。

### R5 价格过滤（新增候选范围，口径待确认）

- 区分语义判断与数值比较：JEV 核实商品类别和文字约束，已知且口径一致的价格由程序比较，不为了确定的大小比较再增加一次模型调用。
- 来源标价、券后实付、按包/件/重量的单价及历史低价不是同一需求；价格单位、比较关系、适用优惠条件、缺价处理等在口径确定后细化。
- 缺价、价格语义或规格不明不等于不满足价格；不能默认 0 元，也不能从任意标题数字推断实付价。
- 历史低价没有现成历史商品价格体系，不能用当前来源价格或模型常识冒充历史证据。是否纳入本任务待用户明确。

### R6 判断复用与其他云端初筛（候选，未批准）

- 优先核实完全相同的有效判断输入能否复用，缓存键覆盖线报内容、需求快照、规则、模型/服务身份及判断依赖的状态；精确输入比对与失效机制不可省略。近似标题、相似商品或高向量相似度不能直接复用最终判断。
- 价格、规格、数量、优惠、有效期及时间基准一旦参与判断，必须进入有效输入与缓存有效性；不得缓存过期优惠或把旧价格结论用于新条件。
- 本地模型方向已放弃。额外云端模型可作为“整批独立语义筛选，候选或不确定项交 JEV”的思路比较；它减少 JEV 调用但增加另一服务的调用，不能默认减少所有服务请求总数，也不能消除初筛假阴性。尚未选择服务或核验其实际能力与收益。
- 不以更换技术名词规避漏报取舍；先用人工核验的线报与需求样例比较收益、逐类召回率和漏报，再提出模型与阈值，不能用现有 JEV 输出单独充当真实标签。

### R7 明确硬条件排除，未知放行（新增候选，未批准）

- 可比较三态的确定性前置检查：只有可信结构化事实明确违反用户设定的硬条件，才排除；条件满足或信息未知均继续进入语义判断，不因为规则未覆盖而丢弃。
- 示例仅说明候选需求：用户限定商城时，可靠字段明确为其他商城；用户设定可比价格上限时，已确认同规格/单位的真实价格超限。用户尚未提供或批准这些硬条件，不自动从自然语言备注推导并启用。
- 当前来源价格不代表券后实付，商城/规格也可能不完整。缺失、歧义、仅标题数字、未知优惠或单位不一致一律不得据此前置否决；不能为了减少请求降低证据要求。
- 这与词表召回未命中就排除的方案不同：规则未覆盖默认放行。收益取决于可验证的硬条件及字段覆盖率，当前没有真实数据证明其能大幅降低调用。

## 本期不包含

- 未经用户选择而新增模型部署依赖、历史线报批量回放、跨来源文章合并、通知渠道改造。
- 本地语义模型、通用生成模型或专用决策模型的部署、硬件购置与选型。
- 基于关键词/正则未命中而跳过语义判断的前置硬过滤。
- 承诺批量判断零漏报，或仅按请求次数宣称费用下降。
- 本轮修改产品代码、发送真实 JEV 请求或通知。

## 阻塞规划的产品决策

用户已确定请求次数优先，否定会因规则覆盖不全而遗漏线报的正则前置方案。当前状态为：

1. 不新增模型的优先基线：独立问题打包＋完全相同有效输入复用，分别验证实际调用减少与重复内容比例；打包不等于减少模型判断，复用也不保证高命中率。
2. 新提出的额外云端路线：支持批量语义判断的云服务处理全量输入，仅将候选或不确定项交 JEV；节省的是 JEV 调用，不保证所有服务总调用减少，仍需处理初筛漏报和额外依赖。
3. 两种输入打包布局仍需对照；最初整批预筛不推荐，正则硬过滤已否定，近似语义缓存不推荐直接复用结论。
4. 新候选：明确硬条件前置排除，未知放行；只按可靠、无歧义且可直接比较的结构化事实否决，剩余全量交 JEV。可与复用、打包组合，用户硬条件和数据口径尚未提供。

当前最高优先级产品问题：是否存在指定商城、明确最高价、规格或品牌等必须满足的硬条件？推荐先检查可验证硬条件排除（未知放行），再叠加现有 JEV 的严格复用＋独立问题打包。无此类条件或来源字段不能可靠比较时，前置排除收益有限。额外云端初筛仅保留为另一备选，是否允许新增服务尚未决定，不能以换服务名字绕过已拒绝的遗漏问题。

后续仍需确认直接使用批量独立结果、凑批等待（此前建议 5 秒，未批准）、价格口径（设定金额上限还是历史低价）、单位和缺价处理；额外云端初筛若入选还须确认质量门槛。不以“减少请求次数优先”代替这些产品决定。可靠 Token 预算、真实重复率与效果尚未核实。收敛后再编写 `design.md`、`implement.md` 和上下文清单，并进行最终方案审阅。
