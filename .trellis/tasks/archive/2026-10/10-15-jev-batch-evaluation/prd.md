# JEV 三种判断模式配置

## 目标与用户决定

在网页 JEV 配置中提供三种互斥的后台判断模式，让管理员选择请求策略。默认保持每条新线报直接进入 JEV，其他两种方式由管理员显式选择。

用户于 2026-10-16 确定：

1. 每条都进 JEV 判断，作为默认模式。
2. 根据批次先做一次 JEV 判断；有可疑或命中，再对该批每条线报分析。
3. 先正则匹配，再进入 JEV 判断。

用户随后确认采用全局规则：在 JEV 页面维护，一行一条，任意规则命中即放行；不扩展每项需求的规则字段。

该最新决定替代此前不提供批次/正则预筛的讨论结论；本地模型仍放弃。不再以其他候选路线替换这三种选择。当前为规划，尚未批准最终设计或进入实现。

## 已核实背景

- 当前一条线报一次请求，全部启用需求分别作为问题置于同一请求：src/lib/worker/evaluator.ts:85—109、src/lib/jev/prompt.ts:56。
- 配置只有连接、超时、并发和每轮任务数字段，没有策略或正则：src/lib/service/config.ts:117、163、221。API 显式校验并转交字段：src/app/api/settings/jev/route.ts:20、58；DTO：src/components/api-types.ts:47。
- 表单及保存：src/app/(admin)/jev/page.tsx:41、57；保存刷新以 version 重建表单：677。每轮任务数和全需求说明在 129、136，需避免被误解成采集批次大小。
- 采集在单频道一次 feed 的事务中去重并为新增非基线条目入队，没有持久化批次：src/lib/worker/collector.ts:180、199—225。evaluator 仅解析单 bulletinId：src/lib/worker/evaluator.ts:209、216、273。
- 列表未命中依赖判断记录，失败还依赖 evaluate:<id>：src/lib/db/repos/bulletins.ts:177—197。不能只结束过滤任务，让成员永久等待，或把过滤冒充逐条模型答案。
- 全部实际调用经统一容量、Key 池和账本：src/lib/service/jev-requests.ts:127、220、285。账本没有批次/阶段关联：src/lib/db/migrations.ts:218。
- 模型约束为 state+最长问题≤32k，state+全部问题≤64k；可靠 tokenizer 未核实。见 research/context-budget.md。
- 连接测试和需求试判分别直接调用 test/dry_run：src/app/api/settings/jev/test/route.ts:36、src/lib/service/dry-run.ts:64—88。

## 需求

### R1 网页配置与默认兼容

- JEV 配置新增互斥选择：「逐条判断（默认）」「批次预筛后逐条判断」「正则预筛后逐条判断」。
- 新安装与存量配置缺少该字段时均默认逐条，不因升级自动启用预筛。
- 保存、刷新、重启后保留；切换模式不自动回放历史线报，切走正则模式仍保留已保存规则。
- 策略仅作用于后台自动处理；连接测试、需求试判仍直接调用，不被预筛吞掉。
- 简短帮助说明请求行为和漏判取舍，不额外增加确认弹窗。

### R2 逐条判断模式

- 每条新线报对全部启用需求进行一次 JEV 调用，保留独立需求结果、多需求合并通知和现有判断语义。
- 不增加门控、正则或第二个模型，不改变默认路径。
- 基线、来源身份去重、并发、退避、重试、Key 池和通知幂等继续适用。

### R3 批次预筛模式

- 对稳定的新线报集合先发起一次整体 JEV 初筛，判断是否存在符合任一需求或信息不足/可疑的成员。
- 仅合法且明确的“全批对全部需求均不相关”可结束该批；成员显示未命中并注明来自批次预筛。
- 有命中或可疑时，该批所有成员逐条调用 JEV；不只分析被点名条目。每条详细判断仍一次携带全部需求。
- “未发现明确命中”不等于“全部明确未命中”；缺答案和失败不得整批排除。
- 推荐批次为单频道一次成功采集后实际新增、去重、非基线集合，不额外等 5 秒凑批。此为技术设计建议，须在最终设计摘要中明确。
- 超预算拆独立子批，每个子批先初筛；单成员集合可直接逐条，避免无意义额外调用。不得静默裁剪正文或遗漏成员。
- 初筛实际失败或非法结果回退逐条；无 Key、容量满、共享退避等未发请求的阻塞继续等待，不以回退绕过限制。
- 批次成员、初筛和逐条展开可重启恢复，不重复展开、遗漏或重复通知。

### R4 正则预筛模式

- 本地匹配通过才按现有逐条方式调用 JEV；未通过不发请求。
- 记录“正则过滤，未调用 JEV”及规则版本，不伪造答案、概率或置信度。页面说明规则未覆盖可能漏报，管理员选择该模式自行取舍。
- 匹配标题、正文及现有品类/品牌/商城/来源价格的明确标签文本，不只匹配标题；多规则 OR，一条命中即放行。匹配文本不裁剪，过大或执行异常回退逐条。
- 启用须有非空合法规则；未配置或语法非法不能保存为有效配置，错误不覆盖旧配置。运行异常回退逐条并记录，不静默过滤。
- 错误为中文，执行有资源边界，不能阻塞整个 worker。
- 已确定在 JEV 页维护一组全局规则，通过后对全部启用需求进行 JEV 判断。采用 JS 正则 source，不写首尾斜杠，固定忽略大小写及 Unicode 模式；空白行忽略，相同规则去重，非空规则内容中的空格保留。
- 最多 20 条有效规则，每条最多 500 个 UTF-16 单元；总规则文本最多 16 KiB。规则校验及执行在线程隔离中完成，具体超时和恢复见 design.md。

### R5 版本、记录与恢复

- 网页可区分逐条 JEV 结果、批次初筛排除、正则过滤；处理失败、待确认和未命中继续区分。
- 模式和规则只影响后续新采集条目；已有批次/条目保留策略快照，不中途混用。升级前旧单条 pending 没有批次信息，沿旧逐条路径完成，不按时间猜造批次。
- 初筛与展开使用同份需求快照；连接配置或模型实质变化后的失效策略在设计明确，真实账本记录实际调用配置。
- 每次真实初筛和逐条请求独立记账，追溯批次/子批/阶段及成员；一次门控加 N 次逐条为 N+1 次，正则过滤不虚增账本。
- 全部调用共享容量、Key 健康与限流；旧租约不覆盖新 owner，业务状态和任务展开保持事务幂等。派生过滤结果不复制门控概率到每个成员或需求。
- 每次领取与真实请求预留使用当前时间，任务租约覆盖实际超时和预筛耗时；不能因为同轮之前任务较慢或中途增大超时，导致正常请求提前失租并被重复调用。

### R6 本轮范围与既有价格语义

- 本轮只围绕三种自动处理模式和必要记录/恢复行为，不新增本地模型、额外云服务或价格模型调用。
- 既有备注中的价格/优惠约束仍参与 JEV；独立目标价、券后换算、单位归一化和历史低价尚未明确，不默认加入本轮。
- 缺价保留 null，来源标价不冒充券后实付，新增策略不改变既有契约。

## 验收标准

| 编号 | 范围 | 可观察结果 |
| --- | --- | --- |
| AC1 | R1/R2 | 新旧配置默认逐条，N 条新线报正常发 N 次请求，每次携带全部启用需求 |
| AC2 | R1 | 网页三模式可保存切换、刷新重启保留，旧客户端省略新字段不覆盖策略 |
| AC3 | R3 | 可容纳子批 N 条被明确全否时仅一次初筛，成员结束等待且可查来源，不通知 |
| AC4 | R3 | 可疑或命中后所有 N 个成员逐条判断，正常共 N+1 次，不只处理点名项 |
| AC5 | R3/R5 | 超时/缺题/非法不造成全批未命中，转逐条恢复；busy/no_key/cooldown 不绕过容量 |
| AC6 | R3 | 拆分不丢成员，单条超限显示失败，不静默截断；重启后拆分/展开无重复任务 |
| AC7 | R4 | 正则通过才调用，未通过可查过滤来源且无模型概率，多规则 OR |
| AC8 | R4 | 空/非法规则不能启用，保存失败保留旧值，运行异常回退且不阻塞其他任务 |
| AC9 | R1/R5 | 模式切换不重放历史或改变已有批次，旧 pending 可完成，需求快照一致 |
| AC10 | R1/R5 | 三模式下测试/试判仍真实调用并记账，容量、Key 健康、通知幂等与 owner 防旧写成立；长耗时后领取和中途增大超时不提前失租 |
| AC11 | R5 | 账本区分初筛/逐条及正确成员，门控费用不按成员倍增，失败不显示未命中 |
| AC12 | R6 | 不引入额外模型/硬件或独立价格体系，保留空价与来源价格说明 |

## 不包含

- 多条直接返回最终结果作为第四种模式。
- 严格/近似语义缓存、跨文章活动合并、额外硬条件过滤。
- 本地模型、额外云初筛、自动生成正则。
- 历史自动回放、独立券后实付计算和历史低价体系。
- 未经另行授权的真实付费模型调用、通知或部署上线。
